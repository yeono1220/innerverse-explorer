각 박스를 클릭하면 파일 경로, 역할, 의존 관계, 그리고 devops·LLM 모듈 추가 시 참고할 확장 포인트가 여기에 표시됩니다.

📔 일기 작성 → 감정 분석 흐름

1
FEDiaryWrite 화면에서 텍스트(+사진) 입력 → lib/api.analyzeDiary() / analyzeVision() 호출
2
BEPOST /api/analyze (multipart) → build_analyzer()가 env ANALYZER_BACKEND에 따라 vllm/claude/dummy 선택
3
LLM5감정(pos·calm·ten·sad·emp) + dominant + keywords + crisis_score + 7라벨 diary 반환 — LLM 실패 시 휴리스틱 폴백
4
DBservices/diaryApi.saveDiaryEntry() → diary_entries insert, 비동기로 POST /api/embed 호출해 pgvector 임베딩 저장
5
FEdiaryStore·emotionStore 갱신 → /diary/result/:id 감정 결과 화면 + 행성 색 반영

💬 모모 챗 (RAG + 장기기억) 흐름

1
FEMomoChat: 입력 시 services/rag.ragContext() — POST /api/embed로 쿼리 임베딩 → Supabase rpc("match_diaries") 유사 일기 검색 (키 없으면 최근 일기 폴백)
2
FEservices/memory.getMemory() → profiles.fact_summary/persona_summary, user_facts, relations로 기억 프롬프트 블록 구성
3
BEPOST /api/momo/reply — RAG 컨텍스트 + 현재 감정 → 공감 답변 생성, crisis_score ≥ 0.6이면 위기 대응 에스컬레이션
4
BE대화 축적 후 POST /api/reflect → 사실/페르소나/관계 추출해 장기기억 테이블 갱신 (Memory 화면에서 조회·삭제)

🔐 인증 → 부트스트랩 흐름

1
FELogin/Signup → services/auth.signIn/signUpWithPassword() (Supabase Auth)
2
DBon_auth_user_created 트리거가 profiles 행 자동 생성 (RLS: owner = auth.uid())
3
FEAuthBootstrap이 세션 감지 → userStore.login() + diaryStore.loadFromDb() 하이드레이션. Supabase 키 없으면 전부 mock 모드로 동작

📊 주간 리뷰 흐름

1
FEWeeklyReview → lib/api.weeklyReview(diaries)
2
BEPOST /api/weekly → 주간 감정 추이·인사이트 생성 (GET /api/weekly/{uid} 조회)
핵심: 백엔드 LLM은 2축 토글 구조. 코드 수정 없이 env만 바꿔 엔진을 교체하고, 새 모듈은 레지스트리에 클래스 하나만 등록하면 됨. 모든 LLM 경로에 휴리스틱 폴백이 있어 API 계약(5감정 스키마)은 항상 유지됨.

✚ DevOps 모듈 추가 시 기존 패턴: 배포 타깃별 파일을 backend/deploy/ 아래에 두고 (예: modal_vllm_server.py), 루트에는 플랫폼 블루프린트(render.yaml, vercel.json)를 둠. 새 타깃(Docker, CI/CD, k8s 등)도 같은 위치 규칙을 따르면 일관성 유지. 시크릿은 전부 env — 코드에 하드코딩 없음, DB 변경은 migration으로만 (BACKEND_AI_PLAN §5 규칙).
